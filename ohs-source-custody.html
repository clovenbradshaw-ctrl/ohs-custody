What this file could not do by itself

The container this register was built in blocks outbound traffic to every domain in it. Probing web.archive.org, nashville.gov, nashville.legistar.com and substack.com all returned 403 with the header x-deny-reason: host_not_allowed. So no source was fetched, no bytes were snipped, and nothing was pushed to the Wayback Machine from here.

The snipping and archiving therefore run on your side, from snip_and_archive.py, which ships alongside this file. It fetches each URL, writes the raw bytes to disk untouched, takes a SHA-256, locates the anchor and records its byte span, then submits the URL to the Wayback Machine and polls until the capture is confirmed. It writes back an enriched manifest. Paste that manifest into the box at the bottom of this page and every row here fills in.

Load the enriched manifest

Paste the JSON that snip_and_archive.py writes to sources.enriched.json. The register redraws with hashes, byte spans and capture timestamps. Nothing is stored, so keep the file.

How a row gets confirmed

  1. Fetch. The runner requests the URL and writes the response body to bytes/<id>.bin with no decoding, no cleanup, no reformatting. Headers go to a sidecar so the content type and server date survive.
  2. Hash. SHA-256 over those exact bytes. This is what makes a later claim about what the page said checkable rather than assertable.
  3. Locate. Three passes, and the row records which one hit. exact-bytes is a straight byte search and the offset is unarguable. normalised-text decodes with the declared charset, builds a character-to-byte index, folds whitespace runs, smart quotes and HTML entities, then maps the hit back to a real byte offset. tag-stripped also skips markup, which is what catches a quote broken by an em or a link, but it can also match across a table cell boundary, so treat those rows as needing an eye. A miss is reported as a miss.
  4. Archive. The URL goes to the Wayback Machine through the Save Page Now API, and the runner polls the job until it returns a timestamp. If a recent capture already exists it is reused unless you pass --force.
  5. Write back. Status, hash, length, byte span and capture timestamp land in the manifest.

Handing the bytes to eoreader7

The bytes/ directory the runner produces is deliberately in the shape the reader wants: content-addressed raw files with a manifest carrying provenance and an offset span per anchor. That matches the pattern already in the lineage, the content-hashed binary store with an export-pointer manifest, and it keeps the anchor addressable at byte_offset rather than at some cleaned-up character index.

The runner stops at that boundary on purpose. It writes readings/<id>.json with the path, hash, media type and anchor span, and leaves a clearly marked adapter function empty. I did not have the v7 tree open, so I am not going to invent the signature for createRecursiveReader and have you debug a call I guessed at. Point the adapter at the real entry point in native/kernel/reading.js and the rest of the pipeline is already fed.

Two documents that would change the piece

The register carries two rows with no URL at all. The MHRC determination and staff investigative report exist and have been quoted, but the outlet that quoted them promised source links in its online edition and did not publish them. The September 2025 audit committee packet holds the audit request verbatim and the adopted scope. Neither is reachable from a search index, which means both are records requests rather than fetches, and neither can be archived until they are in hand.

Until then the piece rests on a secondary source for its central civil rights finding. That is worth naming in the copy rather than smoothing over.
